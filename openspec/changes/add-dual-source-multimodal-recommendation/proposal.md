# Change: 增加双源多模态推荐流程

## Why

当前本地风格、发型和系统衣柜数据已经能提供可追溯的候选，但覆盖度、规则密度和真实用户
反馈还不足以独立承担推荐；纯 LLM 又容易遗漏目录资产、错误套用常识，并且无法解释它与
系统数据为什么不同。若让任一来源单独成为真值，首轮推荐质量和后续数据建设都会失去可审计
的对照。

需要一套过渡期的固定推荐流程：用相同的多模态用户输入并行取得「不含系统知识的自由推荐」
与「含全部适用系统数据的增强推荐」，由确定性代码计算差异、组装用户结果并留下结构化记录。
用户最终的选择和强行为事件作为行为证据回填，为未来规则、目录和群组倾向模型提供数据。

## What Changes

- 增加内部共享的 `DualSourceRecommendationEngine`，并通过三个领域工具
  `recommend-style-directions`、`recommend-hairstyles`、`recommend-wardrobe` 暴露能力；
  固定 workflow 与对话 Agent 均只能调用领域工具，不能绕过工具直接调用 A/B 通道、diff 或 reviewer。
- 把产品路径调整为「推荐并选择风格 → 推荐并选择发型 → 推荐并选择穿搭」，每一阶段都使用
  已确认的上游选择作为约束，不再把风格与发型强制合并成一次原子选择。
- 每个领域并行运行同模型、同参数、同原始多模态输入的两个通道：A 不接收系统目录或规则，
  B 接收全部适用且可审计的系统候选与规则。
- 增加版本化归一化、确定性 diff 与固定组装策略：共识候选优先，其次是系统支持候选，
  最多补一个通过硬冲突检查的探索候选；不使用 LLM 辩论或同步 LLM 裁决。
- 当适用系统数据超过模型上下文时，按稳定 ID 完整分批、并行执行并确定性合并，禁止业务
  Top-K、静默截断或把整篇调研文档塞入上下文。
- 增加结构化的推荐对照、曝光、选择、强结果事件、成本和延迟记录；记录完整版本化用户档案
  与资产引用，而不是复制照片、签名 URL 或原始 prompt/transcript。
- 高差异案例异步触发 reviewer，输出结构化分歧分类和复审建议，但不阻塞、替换或延迟本次
  用户结果。
- 允许 A 通道产生目录外探索条目。缺少目录映射或图片资产时仍可用结构化文字展示和选择，
  同时建立目录缺口与资产生成任务；后续映射不得重写历史推荐。
- 定义逐通道幂等、失败降级、无全身照降级、照片授权、撤回同意与账户删除后的匿名化规则。

## Impact

- Affected specs: new capability `dual-source-recommendation`; modifies `two-round-style-agent`
  的首轮与选择顺序。
- Affected architecture: 推荐应用层、风格/发型/穿搭 provider adapter、三个 Agent 工具、
  首次分析与选择 workflow、异步 reviewer、目录召回和资产缺口队列。
- Affected data: 新增推荐对照日志、通道运行、曝光/选择/结果事件、目录缺口和概念映射等
  持久化对象；现有用户档案、照片、分析、方案与候选通过版本化引用复用。
- Affected privacy: 对照记录进入现有账户删除与人脸同意撤回链路；可识别引用删除后只允许
  保留不可逆匿名聚合。
- Cost: 正常完整路径最多产生 6 次同步多模态推荐调用（每阶段 A/B 各一次）；仅高差异案例
  追加异步 reviewer。逐通道缓存避免重复付费。
- **BREAKING**: 客户端和 workflow 从「风格 + 发型原子选择」迁移为三个分阶段选择点。
