# 设计

只记有真实取舍、且容易被后来者凭直觉改掉的决策。依据强度按仓库惯例标注。

## 决策 1：假发建模为「改变可用发量前提」，而非「绕过约束」

**产品决策 + 逻辑推演。**

两种说法会长出完全不同的代码。「绕过」意味着可行性校验变成可选装饰，下一个人加第二个绕过点
时就没有防线；「改变前提」意味着校验一步没被绕过，只是在正确的前提下算出了正确的约束。

选后者还有一层：`hairConstraints` 文件头那段实测依据讲的是「怎么从信号推断用户**自身**发量」，
假发是在信号之外补了一个用户声明的事实，与那 17 例实测不冲突。用「绕过」的说法则等于宣称
那段实测有例外。

## 决策 2：候选来自确定性排除集，不跑第二轮推荐（**推翻了先前方案**）

**逻辑推演。**

先前的方案是「跑两轮推荐、取差集」：一轮以充足前提、一轮以自身前提，两个列表各自完整。
当时否决「直接用被排除的候选」的理由是：那批东西是**一次模型输出的残余** —— 数量取决于模型
这次挑了什么、没有排序依据，且与 `validateRecommendations` 的「不足就是不足、不回填被排除项」
原则冲突。

**这个理由在生产链路上不成立，所以方案被推翻。** 发型可行集不是「模型产候选、规则事后过滤」
得来的，而是确定性目录投影：先按风格关系取出合规的发型池，再用同一份可行性约束过滤。
被剔掉的部分是**规则算出来的完整补集**，与模型挑了什么无关，也不存在采样波动。于是：

- 不需要第二轮，补集已经在手且完整；
- 不需要第二次付费调用；
- 不需要「核验差集是否真被自身发量挡住」——补集里每项定义上就是被挡住的；
- 与「不回填」不冲突：那条原则防的是拿模型做不出来的东西凑数，而这里每项带明确排除原因、
  单独呈现、带达成路径标签，不混进默认列表充数。

推翻的过程本身也值得记：先前方案还把推导放在首轮分析里，而选定风格方向会让该方案下所有
发型集合失效，那条语义会把它打穿。把推导收进风格选定之后的发型推荐步骤内，问题自然消失。

## 决策 3：排序取模型通道，但**不**用它取舍

**产品决策。**

只取「模型提过 ∩ 被挡住」的交集更精准，但会让入口在多数情况下空着 —— 模型一次只给几个候选。
用户想看的是「戴假发我能多哪些」这个完整集合，所以覆盖优先。

代价必须写明：后半部分没有个人化排序依据，**也没有过模型那一层的脸型判断**。确定性目录投影
本身不做脸型过滤（`appliedFitRules` 恒为空，生产 fit-rule 闸门未通过）。闸门通过后这半边会
自动获得脸型过滤，代价随之消失。

## 决策 4：独立集合（新枚举值），而非默认集合加标记字段

**逻辑推演。**

产品约束是「默认发型列表与从前逐位一致」。已有多处按 `kind` 查集合，其中还有不带排序的
`findFirst`。复用同一枚举值时，只要漏掉一处过滤，假发款就会窜进默认列表，且表现为不确定的
行为。新枚举值让这件事在结构上不可能发生：那些查询自动排除假发集合，一处都不用改。

代价是选定、失效、方案落地这几处要认识第二个集合 —— 一次性成本，换掉的是长期风险。

## 决策 5：形态分档取「被什么挡住」与属性表标注更严的一方

**逻辑推演。**

标注讲款式本身的工艺门槛，被挡原因讲用户为什么做不到，两者都成立才是真的可行。典型例子：
标注说「补量感就够」，但该款式是露额的 —— 发片补不了发际线，必须升到整顶。

## 决策 6：极短露头皮款判为不可行

**逻辑推演（依据强度高于本节其余部分）。**

发型替代从业者**一致不建议**戴假发做寸头类长度：头发极短时头皮成为视觉焦点，任何不自然的
发际线或可见网底立刻暴露；半透明底会露出点状痕迹。这条来自**反向利益方**（假发卖家自己
承认做不到），因此比该领域其余资料可信 —— 该领域几乎所有可检索内容都由卖家或服务商发布。

对应地：完全暴露发际线的造型需要蕾丝前额 + 漂结 + 渐变密度发际线，不是所有价位做得到，
所以「整顶」与「整顶且前额工艺过关」是两个真实档位，不是过度设计。

## 决策 7：fail closed

**产品决策。**

未标注 = 未判定 = 不可行。标错的代价是让用户**花钱**买一顶做不出目标效果的假发，比少推荐
一款严重得多。这也让结构可以先于数据落地：全表留空时能力自动零输出，行为与从前一致。

## 决策 8：达成路径文案用模板，不交给模型

**实测（引用既有实测结论）。**

该表述紧邻「不做医学诊断」红线，而本仓库已有实测表明模型在 prompt 明确禁止后仍会产出
诊断性表述。同理，图生图指令中不出现假发字样：渲染文案按图像供应商逐款校准，引入未校准
语义需整套重测，而图该画的本就是「戴上之后长什么样」。

## 决策 9：出图延后到用户点开入口（**未实现，见 tasks 6.1**）

**产品决策。**

出图付费，而假发是一条用户可能根本不选的路径。入口只显示文字与数量，点开才为这批出图。
这是既有原则「首轮不生成发型预览图，避免把用户还没决定的方向变成出图成本」的延伸。

顺带记录一个查到的事实：默认列表的预览图现在是**自动**请求的（只有防重复守卫，不等用户
动作），也就是每个走到那一屏的用户都会自动产生一批出图开销。本能力没有改它，但它是比假发
入口大得多的一笔，值得单独评估。
