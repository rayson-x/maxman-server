# GLM-5.2 与视觉内容推荐的适配性调研（2026-07-29）

## 结论

**不应把当前照片内容分析/发型与穿搭推荐模型直接切到 `glm-5.2`。** 这不是
模型能力高低的判断：智谱官方将 `GLM-5.2` 定义为旗舰**文本**模型，输入模态与
输出模态均为「文本」。它不能接收本项目的用户照片，因此不满足视觉语义分析和
基于照片做推荐的最小契约。

用户提出「内容推荐应选图像理解强的模型」是正确的方向。智谱体系内应优先评测的
候选是 **`glm-5v-turbo`**，并以当前主链路的 **`glm-4.6v`** 作为基线；不要用
`glm-5.2` 替代视觉模型。官方资料没有提供「人像造型推荐」这个垂直任务的胜率，
所以不能仅凭型号或宣传宣称 `glm-5v-turbo` 一定优于 `glm-4.6v`，需要本项目的
盲测/A-B 结果决定。

## 官方事实核验

| 项目 | `glm-5.2` | `glm-5v-turbo` | 对项目的含义 |
| --- | --- | --- | --- |

| 输入模态 | **文本** | 视频、图像、文本、文件 | 只有后者可读取用户照片 |
| 输出模态 | 文本 | 文本 | 两者都可生成结构化的推荐文本；不是图像生成模型 |
| 上下文 / 最大输出 | 1M / 128K | 200K / 128K | 本项目单轮推荐不需要为 1M 上下文付费 |
| Function Call | 支持 | 支持 | 与现有强 schema/tool call 方案方向兼容 |
| 结构化输出 | 官方模型页明确支持 JSON 等结构化格式 | 官方通用 API 走相同 `chat/completions`，但模型页能力列表未单列「结构化输出」 | `glm-5v-turbo` 接入前必须以本项目 Zod schema 做真实兼容性测试；不能只凭通用 API 假定 100% 等价 |
| 图片 API 形态 | 不适用 | 官方示例支持 `image_url`，也支持 Base64 图片 | 与当前 OSS 短时读 URL 的输入方式兼容 |
| 官方定位 | 长程任务、编码与工程交付 | 视觉编程、GUI/Agent、多模态检索与问答 | 对「可看图」有直接证据；对「造型推荐更好」没有直接证据 |

因此，即使不考虑图片 token，`glm-5.2` 的文本单价也高于当前 `glm-4.6v`，却不能
看图；它既不解决视觉质量问题，也会使推荐成本上升。`glm-5v-turbo` 可解决「模型

`glm-4.6v` 的 5 倍/7.3 倍，切换必须以效果提升证明合理性。

## 当前实现与建议落点

当前服务端并非完全使用 `glm-4v-flash`：

- 基础视觉分析和可覆盖的风格推荐默认为 `glm-4v-flash`，它的模型特点是低成本（当前
  本地规则记录为官方免费 SKU）。
- 首轮带强 schema 的多模态推荐、发型推荐和穿搭推荐默认是 `glm-4.6v`，因为代码
  需要原生 Function Call；可用 `RECOMMENDATION_MODEL` 覆盖。
- 双源推荐的智谱通道默认同样为 `glm-4.6v`，可用
  `DUAL_SOURCE_RECOMMENDATION_MODEL` 覆盖。

建议采用分层模型策略，而非把每一环都升级为旗舰：

1. 保持 `glm-4v-flash` 在低风险、仅提取语义信号的环节，继续记录 token 与调用次数。
2. 将 `glm-5v-turbo` 接为**可配置的候选视觉推荐 provider**，仅用于首轮强 schema
   推荐与/或双源复核，保留 `glm-4.6v` 可一键回退；不要把 `glm-5.2` 放进含照片的
   provider 配置。
3. 先做离线盲测：固定照片集、客户端几何输入、候选目录和提示词，比较
   `glm-4.6v` 与 `glm-5v-turbo` 的 schema 成功率、违禁表述率、候选可执行性、人工
   偏好、输入/输出/图片 token、P50/P95 延迟。脸型仍由客户端测量，模型不得重新判定。
4. 设定上线门槛：新模型只有在安全守卫零回归、schema 成功率不下降，并且质量提升
   足以覆盖增量成本时才灰度。流量按业务调用记录 `provider`、`model`、
   `inputTokens`、`outputTokens`、`cachedInputTokens`、`imageTokens`（若响应给出）和
   费用快照；没有官方可确认价格时状态必须是 `unknown`，不能按 ¥0。

## 需要在真实调用中验证的兼容项

- 在同一 `chat/completions` OpenAI-compatible 适配器下，`glm-5v-turbo` 对现有
  Function Call / Zod schema 的参数、完成原因与 usage 字段是否与 `glm-4.6v` 兼容。
- `thinking` 显式关闭时的稳定性、延迟和是否将 reasoning token 单列到 usage；成本
  hook 必须保存厂商原始 usage 摘要，避免漏计。
- 多张 OSS 预签名 URL 输入、图片尺寸、失败重试与超时下的 token/费用记录是否准确。
- 用项目的安全样本验证不产生医学诊断、年龄数字、性别倾向或重新判定脸型等违禁内容。

本调研没有改动生产代码、环境变量或价格迁移；在未完成上述验证和价格规则快照前，
不应直接切换线上默认模型。
